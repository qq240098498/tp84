# tp84 依赖台账与版本核查平台

一个本地小工具：把各个项目用到的依赖集中登记起来。页面上先建项目，再往项目下面登记依赖名称、版本、许可、责任人与状态；同一个依赖被两个项目用到时，版本高低一眼能比出来。依赖名写得不合规矩、版本不是三段数字、同一个项目里重复登记同一个依赖，保存时当场就会指出来。

责任人单独有一块汇总区：每个人名下压着多少条、具体是哪些项目的哪些依赖都能展开看；没写责任人的登记单独归在「未指定」一组，不会混到任何人名下。选定一批登记可以批量转交给新的人，执行前先给出预演（改哪些登记、转交前后各责任人条数怎么变），执行后双方条数对得上；每一次转交都留下时间、操作者与明细，撤掉责任人（转交给空）也同样留痕。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5084>

端口固定为 `5084`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，新建登记时会把它带进责任人；批量转交必须先填操作者，记录里要写清是谁办的
2. 责任人区按人汇总名下条数，点每行前面的箭头能展开看到具体是哪些项目的哪些依赖；没写责任人的登记单独归在「未指定」一组
3. 在责任人区勾选要转交的登记（每组前面的勾选框可以整组选），在上方填好转交对象后点「预演转交」
4. 预演弹层里列出会改动哪些登记、已经在新责任人名下会跳过的条数，以及转交前后各责任人条数的变化；确认无误后再执行。转交对象留空表示撤掉责任人，这些登记会回到「未指定」一组
5. 转交记录区按批次列出每一次转交：时间、操作者、从谁那里（各多少条）转给谁，展开能看到每一条登记的项目、依赖名与版本
6. 项目区列出项目名称、负责人、说明与这个项目下已经登记了多少条依赖；可以新增项目，也可以改名、换负责人、删除
7. 依赖登记区顶部可以按项目、状态、许可筛选，再按依赖名、责任人或者备注搜索，右上角刷新按钮重新拉取一次
8. 点新建登记，选好所属项目，填上依赖名称、版本，按需要补许可、责任人、状态与备注；列表里点编辑会把这条登记回填到表单，编辑时改动责任人也会在转交记录里留下一条
9. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除项目与删除登记都会先确认

项目下面还挂着依赖登记时不允许删除项目，页面上会写清还剩多少条、例如哪几条，先处理这些登记再删。

## 登记口径

- 依赖名称以小写字母或数字开头，可以用小写字母、数字、点、下划线、短横线与斜线，最长 60 个字符；带范围的写法例如 `@types/node` 也按这个口径登记
- 版本写成三段数字，例如 `2.7.18`，需要时可以带一段预发布后缀，例如 `5.0.10-rc.1`
- 许可按实际名称填写，例如 `MIT`、`Apache-2.0`、`BSD-3-Clause`；还没确认的可以留空，列表里会显示成未填
- 责任人可以留空，表示这条依赖还没有定人
- 状态只有三种：在用、待升、已弃用
- 备注用来写为什么用这个版本、有没有待办，最长 200 个字符
- 同一个项目下不允许出现同名的依赖，同一个依赖在不同项目里各登记各的、互不覆盖

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "projects": [...], "deps": [...], "transfers": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。旧版本数据文件里没有 `transfers` 字段时按空数组处理，已有的转交记录只追加不改写，记录里存了登记当时的项目、依赖名与版本快照，登记以后再改名也不影响历史记录。

## 接口一览

| 方法   | 路径                       | 说明                                                  |
| ------ | -------------------------- | ----------------------------------------------------- |
| GET    | /api/health                | 服务状态检查                                          |
| GET    | /api/projects              | 项目清单，附带每个项目的依赖条数                      |
| POST   | /api/projects              | 新增项目                                              |
| PATCH  | /api/projects/:id          | 修改项目的名称、负责人或说明                          |
| DELETE | /api/projects/:id          | 删除项目                                              |
| GET    | /api/deps                  | 依赖登记列表，支持按项目、状态、许可筛选与关键词搜索  |
| POST   | /api/deps                  | 新增依赖登记                                          |
| GET    | /api/deps/:id              | 查看单条依赖登记                                      |
| PATCH  | /api/deps/:id              | 修改依赖登记（责任人变化时自动补一条转交记录）        |
| DELETE | /api/deps/:id              | 删除依赖登记                                          |
| GET    | /api/owners                | 按责任人汇总：每个人（含未指定）的条数与明细          |
| POST   | /api/transfers/preview     | 批量转交预演：将改动的登记与转交前后条数对账，不落盘  |
| POST   | /api/transfers             | 执行批量转交，同批共用一个批次号并按登记逐条留痕      |
| GET    | /api/transfers             | 转交记录，按批次倒序，支持 `limit`                    |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
